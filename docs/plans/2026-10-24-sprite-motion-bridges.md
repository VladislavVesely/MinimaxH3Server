# Sprite motion bridges

Approved behavior: autonomous `/sprite` accepts two existing generation folders; create a generated one-shot bridge from A's final exported frame to B's first. Latest manifest-listed export by default, optional explicit revisions. New folder; never alter either input. No GPT Image, one H3 job, no automatic paid retry. Antialiasing remains off by default.

Implementation: `beginBridge` validates metadata and confined regular endpoint PNG paths, snapshots/hashes endpoints, inherits A's output geometry/FPS/style flags, discovers first/last support, and reserves a shared key against both palettes. `source` prepares both snapshots with contain scaling and normalized anchor alignment, rejects visible clipping/inconsistent dimensions, validates key backgrounds and records transforms. `animate` uploads two pinned endpoints and compiles the current frames contract; existing preflight, durable IDs and receipt-only recovery apply. `finish` uses the existing RGBA/GIF exporter and saves linkage in `bridge.json` and `animation.json`. Slash-command instructions route natural-language bridge requests through the complete workflow and require inspection of both endpoints.

Limitations: geometry does not infer semantic character size or reconcile different identities/cameras. H3 endpoints are conditioning, not pixel locks or velocity guarantees. The output is the bridge only, not automatic assembly of all three clips. Reprocessing may retime the bridge independently of H3 minimum duration. No temporal matte stabilization added.

Verification: 31 TypeScript + 21 Python tests, typecheck, dependency check, diff whitespace check. Tests cover full local preparation/export with real Pillow/FFmpeg and injected inference, latest/pinned exports, source preservation, path traversal/symlinks, endpoint tampering, metadata mismatch, anchor clipping, unsupported last-frame mode, distinct first/last payloads and ambiguous receipt recovery. The actual native GenerationInput/Preflight/project/run/Generate validators accept the first+last frame payload in isolated offline stores (zero jobs). Live discovery and frame guide read-only confirmed existing endpoint support. No paid bridge generated; real motion and join quality remain for the operator's first trial. Controller/daemon changes are unnecessary for this Pi extension-only feature.
