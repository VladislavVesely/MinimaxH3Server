# MP3 export and consistent download actions

## Design

- Retain Download MP4 as a native download link, sharing button styling, focus and hover treatment.
- Add explicit Download MP3 for completed/unexpired Current and History videos. Do not trigger generation, installation or exports while polling.
- Use server-side PyAV/libmp3lame rather than downloading a browser codec or depending on browser-specific audio decoding. Encode audio only at 320 kbps, without changing the original MP4. Clearly distinguish lossy MP3 from stream-copy MP4 and PNG frame export.
- Follow the existing authenticated last-frame export path: owned descriptor, bounded child, concurrency gate, safe filename, no-store response, strict controller proxy allowlist, target-epoch check before browser download. Reject absent audio explicitly.
- Controller Python changes require a new process. Preserve existing processes/private joiner workspaces, use a separate immutable build destination and communicate the new endpoint. Gate MP3 on the controller capability to keep older controllers truthful.

## Implementation and verification

Implemented `audio_export.py`, daemon/controller audio endpoints, proxy allowlist, MP3 UI control and shared button-link styling. Tests cover auth, missing jobs/audio, descriptor closure, unchanged source, child failure/deadline, concurrency, output limits, proxy confinement, browser target changes and explicit-only downloads.

Actual Ubuntu export of an existing completed video decoded successfully: source and MP3 audio durations both 5.184 seconds; independent ffprobe identified stereo MP3 at 320 kbps. Chrome and WebKit downloaded actual MP3 files from both tabs and the original MP4. Current membership was simulated by withholding one existing completed job from the initial read; no generation was submitted. See validation notes for rollout and remaining local codec-test skips.
