## Stable background prompting and review

Read the EXACT live model/mode guide before authoring; H3 frame mode currently owns English `integrated_multimodal_description`, `overall_soundscape`, `non_diegetic_music` and the compiler-owned picture alignment. Unknown model contracts are not given invented sections. Do not invent a negative_prompt, guidance_scale, numeric weights, masks or physical colour lock when the returned contract offers none. Complete silence/N/A is appropriate only when intended by the request.

New central background wording version2 inserts a positive image-plane description after `[Shot 1]`. Include a **plain-language colour name plus exact RGB/hex**, not just numbers; hold the same hue, saturation and brightness in **EVERY frame**, explicitly at the opening, throughout all intermediate movement and at the closing image. Describe the plane as flat and unlit; foreground lighting acts only on foreground content. Do not enumerate alternative colour/scenery words. This is model guidance, not a physical compositor layer or bit-exact colour lock.

Exact-key English names/descriptions for the native primary blue/green/red live beside the wording in `sprite-defaults.json`. No blue string is applied to another selected key. Arbitrary keys retain their exact RGB/hex with a neutral reserved-colour description instead of guessing a misleading hue; an author may describe the actual selected colour in the owned scene section. Key compatibility/palette validation is unchanged.

The generic paragraph does NOT impose the controlled sample's fixed camera/exposure or an actor-specific shape. It preserves explicit camera motion and arbitrary foreground action. Substitution is idempotent and snapshots are durable. Existing prepared folders retain their saved older wording; existing compiled/submitted prompts, sources and receipts remain unchanged on reload. A new policy is not permission to rewrite/replay them. Inspect a saved policy before resuming; a changed-prompt paid experiment requires explicit authorization, never an automatic same-prompt/new-seed repair.

## Bounded automatic regeneration

Only **confirmed background drift** on an initial native result can use the saved allowance (default1repair/2total H3 jobs,0or2repairs explicit options). Same art/action/profile/settings, next recorded seed. Run limits and per-shot revisions are declared BEFORE submission. Original MP4/unique RGBA ZIP, full settings/prompt/raw diagnostics/review and receipts are preserved in `attempts/<job>.json`. Workspace `sprite-background-failures.jsonl` is append-only/searchable, records model/size/seed/prompt hash/evidence location, contains no credentials. New MP4s get unique attempt filenames; failed originals are never overwritten. No new image call.

Durable retry preparation/ID/receipt happens under the existing folder lock. Retry submission releases/reacquires it safely. On interruption use status: pending recovery continues finish; ambiguous POST continues animate only to resolve the SAME request. SAME processing options must resume. Simultaneous calls cannot exceed the original allowance. Existing/legacy jobs never gain a budget implicitly.

After allowance exhaustion, `background_rejected` blocks export/finish loops; report saved evidence. Unknown/occluded measurements are review-needed, not a paid retry. Network/exporter/checksum/provenance failures, missing archives, broken source or ordinary feedback NEVER authorize a fresh inference. A native job cannot silently switch to local/saved-video keying. `options.transparency:"local"` or `"experimental-server"` BEFORE generation explicitly chooses those distinct alternatives; their original processing safeguards remain.
